🛠️ DRP (IT 복구)
📌 Severity Level (상황등급) 기준표 (클릭하면 접기/펼치기)
• SEV1이 가장 심각(전사 위기), SEV5는 정보성/관찰 수준입니다.
• 실행 완료 시 선택한 상황등급이 로그에 저장되어 Operation Center / Audit Center에서 증적으로 활용됩니다.
등급 정의(요약) 예시 권장 대응
SEV1 (최고) 전사/대규모 서비스 중단, 핵심 시스템 장시간 불가, 대외 리스크 가능 로그인 불가 + 결제/핵심 서비스 전체 장애 비상대응 체계 가동, War-room, 24/7 복구
SEV2 (높음) 핵심 기능 영향/부분 중단, 다수 사용자 영향 인증/SSO 장애로 다수 시스템 접근 불가 즉시 조치, 1~2시간 단위 보고
SEV3 (중간) 일부 기능 영향, 우회 가능, 제한된 사용자 영향 특정 시스템 성능저하, 일부 API 오류 업무시간 내 복구, 재발방지 등록
SEV4 (낮음) 경미한 결함/지연, 영향 제한 모니터링 경고, 비핵심 기능 오류 계획 수리, 정기 배포로 수정
SEV5 (정보) 관찰/점검/정보성 이슈 테스트 로그, 경미한 알림 기록 유지, 추세 관찰

DR 시스템 & Runbook

System Registry 기반으로 “표준 시스템”을 선택하고, DR Runbook을 실행 로그로 남깁니다.
Registry 키: localStorage["bcms_system_registry_v1"] / DR 로그 키: localStorage["bcms_drp_exec_logs"]

예정 기능

• 시스템 등록(분류/소유부서/중요도/RTO/RPO)
• 백업 정책(주기/보관/복구 검증)
• Runbook(복구 단계/검증/롤백)
• DR 테스트 이력(일자/범위/결과/CAPA)

권장 템플릿 구조

1) 시스템 개요/아키텍처
2) RTO/RPO & 우선순위
3) 백업/복구 절차(Runbook)
4) 복구 검증(서비스 체크)
5) 테스트 기록/개선조치(CAPA)
